# 已知限制与后续

本轮代码缺口与验证结果统一见 [B 后端修复与验收](B后端修复与验收-2026-11-07.md)。

1. 当前实例仅 Windows 认证，演示入口仍是开发者集成身份；独立受限服务器登录未部署。26 项探针验证的是 EXECUTE AS USER 模拟入口与业务权限。正式运行应由管理员配置专门受限 Windows/SQL 登录并加入 teabar_web_app，补实际连接验证，不使用 dbo 入口作正式部署；后端已支持对应连接参数。本轮未修改服务器认证模式或系统用户。
2. B 提供可运行参考模板、稳定契约和报告章节；C 最终模板合并、真人浏览器截图/演示及外部确认仍属于后续联调，未冒充完成。
3. 无真实支付、自助注册、找回密码；HTML/API 只模拟支付结果。按既定范围只实现店长补库/盘点最小写入，完整商品/规格/原料/员工/排班维护不在本轮 B 最小闭环内。
4. 测试库会保留订单/快照/幂等回执，不是干净演示库；测试命令仅连接隔离库。新建库工具拒绝覆盖已有库；不在应用或演示流程提供删除数据库功能。当前 Work 已按空环境链准备，后续用户写入会自然改变样例状态。
5. 幂等回执按同一数据库SID、区分大小写token保留，不自动过期。API 无键请求维持原“每次独立下单”语义，网络重试必须复用 Idempotency-Key。
6. B 初始化新增 WebOrderRequest 后为18张物理表、20条FK；A 原184回归含精确17表/19FK基线，必须在安装B扩展、写入Web数据之前运行。B扩展安装后使用应用回归与权限探针，不能把A旧结构数量当作扩展后的失败判据。
7. A 冻结迁移中的合法 `_`/`-` 字符问题已由 B 初始化的兼容补丁修正；源迁移仍保留原样。后续 A 可在下一版整合补丁。原反馈中“NVARCHAR字节长度与字符数不一致”的结论已撤回。
8. 开发时缺失密钥会生成进程随机值；重启旧Cookie失效。demo/production 必须显式配置随机密钥；本地HTTP需关闭Secure Cookie，HTTPS时开启。生产证书、并发容量与压力测试仍需部署环境验收。
