# 后端技术说明

## 分层和授权

Browser → Route → Service → DAO → SQL Server 的 teabar_api 视图/过程。业务输入全用 ? 绑定；身份切换为服务端固定白名单，属于数据库基础设施。健康 SQL 已归入 DAO。

Web 会话只保存账号标识、版本、角色和主体名。每次受保护请求通过认证过程重新核对账号、映射及授权；Route 用 session_scope 控制角色，Service 再验证同一连接上的可信请求上下文。非 HTTP 的 Service 调用从 SQL 查询实际角色，无法靠任意传参自报身份。员工工作角色不新增 employee_id/实际制作人关系，按 D03 与 v1.0 接口的既定范围。

匿名菜单使用独立 `web_public WITHOUT LOGIN`，只获三项菜单/规格/加料 SELECT 权限，不复用购买身份。

## 连接和结果

首次连接前设置 `pyodbc.pooling=False`。每次作用域建立新连接，autocommit=True；切换身份前校验允许名单；退出时先回滚残留事务、REVERT、关闭游标/连接。身份清理失败丢弃连接并报 503，重复关闭句柄不会掩盖原异常。普通查询/过程公共执行入口在 dao/common.py，结果读取逐个 nextset 消费，确保 SQL 后续结果中的提交错误不会被误认为成功。当前接口不依赖输出参数或过程 RETURN 值，不伪造它们。

ODBC 配置值统一使用花括号引用并转义右括号，支持含分号/括号的合法配置。连接与查询超时分别 5 和 30 秒。

## 下单与事务

普通 API 可继续调用原 JSON 包装，三个数组分别序列化绑定；HTML 多商品购物篮带 `request_token`，API 可传相同字段或 `Idempotency-Key` 请求头。相同账号、相同 token 与相同载荷回放第一次成功结果；相同 token 换载荷为 409；不同账号互不冲突。无幂等键的旧 API 请求按普通独立订单处理，调用方重试应复用同一键。

`usp_PlaceWebOrder` 使用数据库 SID + 二进制 token 主键和相同输入哈希的应用锁串行化，再在同一外层事务内调用唯一 JSON/TVP 核心、保存回执并提交。失败不留回执/订单/扣库。锁资源为固定长度 SHA256；原核心下单、快照、库存与价格规则没有复制。回执表不向业务用户开放直接读取/写入。

订单及明细编号为 O/I + 9 位大写十六进制。只识别 PK_SalesOrder/PK_OrderItem 唯一冲突且确认 @@TRANCOUNT=0 后，重新生成订单和全部明细引用，最多三次；其他唯一冲突不重试。

退款、状态推进、首次完成积分和补库仍由原数据库过程保证原子性。应用不另外启动跨请求长事务。

## 响应与日志

AppError 对外只发送固定 code/message；547、229、2601/2627、业务号、连接失败、死锁/锁超时分开映射。HTML 失败直接重渲染原页并保留可安全回填的字段，密码不回填，不返回4xx重定向。CSRF 覆盖所有写请求；Cookie 为 HttpOnly/SameSite=Lax，HTTPS 可启用 Secure。

每个请求生成随机 request_id；日志包含时间、操作端点、方法、账号ID、角色、错误码、SQL原生号/SQLSTATE、HTTP结果、耗时，响应带 X-Request-ID。退出或失效请求保留原操作者快照。未知异常记录代码帧位置和异常类型；不记录原始异常参数、密码、连接串、完整表单或任意SQL输入。

## 初始化与版本

`init_web_accounts.py` 在同一管理员事务内初始化账号/权限并安装 B 扩展，支持幂等执行与 dry-run。后置字符类兼容补丁修正已确认的 BIN2 `_`/`-` 拒绝问题，不改变 NVARCHAR 字节长度规则或原业务模型。A 原迁移源保持冻结，后续重新建库必须继续安装 B 扩展。

本轮实际环境 Python 3.12.4、Flask/Werkzeug 3.0.3、pyodbc 5.0.1、pytest 7.4.4；requirements 已声明兼容范围。旧提交的 Python 3.12.16/31 passed 属于历史证据，不能当作本机现状。
