# v0.1 数据库对象清单

核对日期：2026-11-06。对象名称来自当前 SQL 静态审计；数量与第一阶段系统目录核对记录交叉比对。本次没有连接 SQL Server，实际安装状态仍需在第 4 轮通过 SSMS 复现。

## 2. 关键字段、默认值和计算列

### 2.1 后补或特殊字段

- `SalesOrder.guest_id uniqueidentifier NULL`：由 `constraint.sql` 添加；与 `member_id` 必须二择一。
- `OrderItem.sub_amount`：`CAST(unit_price * quantity AS decimal(10,2)) PERSISTED NOT NULL`，不能直接插入或更新。
- 历史快照字段：`product_name_snapshot`、`base_price_snapshot`、`unit_price`、`spec_name_snapshot`、`price_delta_snapshot`、`addon_name_snapshot`、`price_snapshot` 和 `OrderItemIngredient.amount`。

### 2.2 命名默认约束

源码最终状态包含 12 个命名默认约束：

- `DF_Employee_status`
- `DF_Member_points`
- `DF_SalesOrder_order_time`
- `DF_SalesOrder_status`
- `DF_Product_status`
- `DF_Ingredient_stock`
- `DF_Ingredient_status`
- `DF_OrderItem_quantity`
- `DF_ProductSpecification_price_delta`
- `DF_ProductSpecification_status`
- `DF_AddOn_status`
- `DF_PrincipalBinding_Active`

`db_creation.sql` 中部分默认值最初以内联未命名方式建立；`constraint.sql` 负责兼容、核验和在缺失时补建命名默认约束。

## 3. 完整性约束

### 3.1 主码、唯一约束和外码

- 主码：16 个，每张物理表 1 个。
- 唯一约束：6 个，分别为 `DutyRoster(employee_id,start_time)`、`Member(phone)`、`Specification(spec_type,spec_name)`、`Specification(spec_id,spec_type)`、`AddOn(addon_name)`、`PrincipalBinding(principal_name)`。
- 外码：19 个，详见第 1 节表格。

### 3.2 CHECK 约束

当前脚本中可识别 46 个命名 CHECK，按职责归类如下：

- 标识和名称非空白：Employee、Member、SalesOrder、Product、Specification、Ingredient、OrderItem、DutyRoster、AddOn、ItemSpec、ItemAddOn。
- 数值范围：工资、积分、订单金额、商品价格、库存、数量、成交价、配方用量、加料价格与用量、消耗快照、规格系数。
- 枚举状态：员工状态和岗位、订单状态、商品状态、原料状态和单位、规格类型、商品规格状态、加料状态。
- 跨字段规则：`CK_DutyRoster_Time`、`CK_SalesOrder_Owner`、`CK_PrincipalBinding_Identity`。
- 计件规则：`CK_Ingredient_PieceStock`，并由受控过程继续校验配方与规格组合的整数用量。

`constraint.sql` 的“44 项通过”是验证用例数量，不是 CHECK 约束数量，两者不能混为一谈。

## 6. 数据库角色、用户和权限边界

| 数据库角色 | 演示用户 | 主要能力 | 关键拒绝规则 |
|---|---|---|---|
| `teabar_customer` | `demo_guest_a`, `demo_guest_b` | 浏览、本人下单、读取和退款本人排队订单 | 不读全部订单或会员表，不直接写业务表 |
| `teabar_member` | `demo_member_a`, `demo_member_b` | 顾客能力，加本人资料、积分和消费记录 | 不读会员名单，不直接改积分 |
| `teabar_clerk` | `demo_clerk` | 工作订单、状态推进、协助退款、会员登记与更正 | 不补库、改价、查工资或经营统计 |
| `teabar_manager` | `demo_manager` | 店员能力，加商品、库存、配置、员工、排班和经营统计管理 | 不直接改历史快照，不授予角色或用户权限 |

六个演示用户均为 `WITHOUT LOGIN`，只用于 `EXECUTE AS USER` 回归，不是 Web 登录账号。四个业务角色都不获得业务表的直接写权限，写操作通过 `teabar_api` 过程完成；`role.sql` 还显式拒绝角色和用户管理能力。详细逐对象授权仍以 `role.sql` 和 `docs/role.md` 为准。

## 7. 对象来源结论

- `db_creation.sql` 不是完整 v0.1：它只建立初始 15 张业务表。
- `constraint.sql` 增加游客归属和配方复合外键，并统一约束与默认值。
- `role.sql` 增加身份绑定、安全主体和受控业务接口。
- `view.sql` 增加正式查询与统计视图。
- 查询和演示脚本不构成最终持久结构，除非执行被中断导致临时演示对象未清理；复现时应检查这一异常情况。
