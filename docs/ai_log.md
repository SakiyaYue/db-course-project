# AI 使用记录

整理日期：2026-10-06。项目：蜜雪冰城单门店数据库课程实验。

本记录根据当前 SQL、设计文档、验证说明和实验截图整理。下列求助内容是主题摘要，不是原始对话的逐字转录；未保存的提示词、模型版本及个人分工不作补记。业务范围和规则以小组确认结果为准，AI 用于辅助实现、审查和材料整理。

## 1. 需求、关系模式与建库

**求助摘要：** 将单门店商品、配方、库存、规格、加料、订单、会员、员工和值班需求整理为关系模式，检查 ER 图、数据字典与 SQL 是否一致。

**辅助成果：** 建库与样例装载分离；整理主外键、唯一约束、默认值和字段域；提供 CRUD、取消返库、完成订单积分和值班团队的演示说明。

**小组确认与调整：** 规格类型采用温度／糖度／杯型；明细小计为持久化计算列；成交价格、名称及原料消耗保留快照；积分按订单金额向下取整，在首次完成时结算；订单按创建时间匹配全部值班员工。初始化样例为15张业务表、232条记录，CRUD演示结束回滚。

**验证依据：** [建库与 ER 图一致性检查](建库与ER图一致性检查.md)保存2026-10-05的确认和 tempdb 回滚验证记录。该记录中的结构核对属于当时版本，完整安装后的结构见第5节。

## 2. 查询与视图

**求助摘要：** 按商品、库存、购买试算、订单、会员、排班和经营统计编写18项查询、13个正式视图，并审查汇总、规格计算及退款诊断。

**辅助成果与审查修正：**

- Q06检查每种开放规格类型是否明确选择一项，默认选项也不能省略；缺选时不报价，Q07判定不可购买。
- 规格原料视图保留基础量乘系数后的精度和容量，避免转回 `DECIMAL(10,2)` 时溢出或提前舍入。
- 排队订单缺少某条明细的消耗快照时，区分“快照缺失”和“状态不允许退款”，阻止输出不完整的可返量。
- 经营统计分别汇总订单与明细，避免连接后重复累计订单金额；补充简短查询演示和视图创建、修改、删除演示。

**采用规则：** 多类型规格系数相乘，缺省系数为1，零系数保留；加料独立计算。历史消耗读取成交快照，不按当前配方重算；购买试算不创建订单或扣库。

**已有验证记录：** 2026-10-06在 tempdb 独立 schema 和回滚事务中执行建表、装载、两次视图脚本及完整查询，24项检查通过。包括漏选规格、默认项漏选、类型不匹配、整类停用、缺快照、订单状态及数值边界。正常方案为18元＋9元＝27元；样例日期2026-10-04经营结果为3单、5杯、46元，平均客单价15.33元。

**对应材料：** [查询说明](第四周查询.md)、[视图说明](第四周视图.md)、[query.sql](../query.sql)、[view.sql](../view.sql)、[query_demo.sql](../query_demo.sql)、[view_demo.sql](../view_demo.sql)。

## 3. 完整性约束

**求助摘要：** 独立实现 `constraint.sql`，保留已有约束、补齐缺失约束，并用合法和非法数据证明约束实际生效。

**辅助成果：** 补充游客归属 `guest_id`、会员／游客二择一、非空白编号、计件库存整数及规格规则引用基础配方的复合外键；重新核验并启用 FK/CHECK；安装与验证支持重复执行。

**采用规则：** 候选码、外键、非空、检查和默认值分工明确；不以禁用约束绕过旧数据错误。旧非会员订单的占位游客ID只用于结构兼容，不代表已还原真实会话或完成认证。反例检查实际错误号及目标约束或字段，不将任意报错视为通过。

**已有验证记录：** [约束说明](constraint.md)记录2026-10-06独立 SQL Server 测试库中44/44项正反例通过，重复执行通过。测试记录回滚，安装对象保留在测试环境；未升级现有 TeabarDB。约束验证本身不证明身份隔离、状态流转及积分结算，应结合角色脚本。

**对应脚本：** [constraint.sql](../constraint.sql)。

## 4. 角色权限与业务操作

**求助摘要：** 为顾客、会员、店员、店长实现最小权限、本人数据隔离和受控业务操作，验证正常操作与越权拒绝。

**辅助成果：** `role.sql`建立四种数据库角色、六个 `WITHOUT LOGIN` 演示用户、身份绑定辅助表、接口视图与存储过程。下单、扣库、退款、状态推进、积分结算、补库盘点和配置维护均通过受控操作执行。

**采用规则与修正：**

- 购买身份取自管理员维护的数据库用户 SID 绑定；不信任调用者传入的会员、游客归属或客户端会话字段。
- 创建订单、明细、选择与快照及扣库一起成功或失败；只允许排队订单退款，重复退款或完成不能重复返库、加分。
- 店员读取当天及全部未完成订单；店长可查全部历史与经营数据，但不能直接改历史快照或授予数据库权限。
- 计件原料逐杯检查。启用商品规格时检查全部可用类型组合，拒绝单项合法但组合产生小数的用量，并回滚本次配置变更。
- 员工业务岗位、在职状态和数据库角色成员关系分别维护；模拟支付参数只用于课程演示。

**已有验证记录：** [角色说明](role.md)记录2026-10-06独立测试库中84/84项正常、越权及业务用例通过，重复执行通过。其中10项覆盖计件规格组合、备选和停用选项、零系数及合法消耗快照。非法操作同时检查错误号与前后业务数据哈希；另验证无外层事务时的配置回滚和事务计数归零。现有查询、视图及CRUD脚本在角色安装后执行通过，未升级现有 TeabarDB。

**对应脚本：** [role.sql](../role.sql)。
