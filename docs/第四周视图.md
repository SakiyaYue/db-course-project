# 第四周视图说明

本文说明 `view.sql` 中创建的 13 个视图。视图用于保存经常重复使用的连接、汇总和判断逻辑，方便后续查询直接读取。视图本身不保存一份新的业务数据，基础表发生变化后，再查询视图即可看到新结果。

依据为 `第四周查询.md`、`../../baseline.md`、`../第四周任务讲解.docx` 和 `第二周关系模式与数据字典.md`。视图名称统一使用 `vw_` 开头，并通过 `CREATE OR ALTER VIEW` 创建，因此 `view.sql` 可以重复执行。

## 1. 视图内容

**商品与可选配置（V01—V04）**

### V01 商品目录视图 vw_ProductCatalog

供顾客查看和搜索商品目录，对应 Q01。

- 来源表：Product。
- 一行含义：一个商品。
- 主要内容：商品编号、名称、基础价、说明和商品状态。
- 使用方式：在调用时筛选在售商品和名称关键词。

示例：

```sql
SELECT product_id, product_name, base_price
FROM dbo.vw_ProductCatalog
WHERE product_status = N'在售'
  AND product_name LIKE N'%奶茶%'
ORDER BY base_price, product_id;
```

基础价格不包含规格和加料价格。视图保留全部商品，是否只看在售商品由调用查询决定。

### V02 商品规格视图 vw_ProductSpecification

供顾客查看一种商品可以选择的温度、糖度和杯型，对应 Q02。

- 来源表：Product、ProductSpecification、Specification。
- 一行含义：一个商品的一项规格配置。
- 主要内容：商品信息、规格类型、规格名称、加价和配置状态。
- 使用方式：按商品编号查询，同时筛选在售商品和可用配置。

P001 在初始化数据中有 9 项可用规格。此视图表示商品允许选择的规格，不表示某笔订单已经选择的规格。

### V03 规格原料规则视图 vw_SpecificationIngredientRule

供店长查看规格如何调整基础配方，对应 Q03。

- 来源表：Product、ProductSpecification、Specification、Recipe、Ingredient、SpecificationIngredient。
- 一行含义：某商品的一项规格作用于一种基础原料。
- 主要内容：基础用量、显式系数、实际采用系数和调整后用量。
- 计算规则：存在规则时使用规则中的系数；没有规则时按系数 1 处理。

`explicit_factor` 表示数据库中是否有明确规则，`effective_factor` 表示实际采用的系数，`adjusted_amount` 表示调整后的原料量。系数为 0 时表示该规格取消这种原料，例如无糖或去冰。

该视图一次展示一项规格的影响。顾客同时选择糖度、温度和杯型时，需要按 Q07 的方法合并多个规格系数。

### V04 加料可用视图 vw_AddOnAvailability

供顾客查看加料价格和单份可选情况，对应 Q04。

- 来源表：AddOn、Ingredient。
- 一行含义：一种加料。
- 主要内容：价格、每份用量、对应原料、库存和状态。
- 判断结果：`can_choose_one` 表示当前库存是否足够选择一份，`availability_reason` 给出原因。

此处只判断一份加料。整张订单选择多份加料时，仍需按 Q07 汇总后检查库存。

**原料库存（V05）**

### V05 原料库存视图 vw_IngredientStock

供店长查看所有原料库存，对应 Q05。

- 来源表：Ingredient。
- 一行含义：一种原料。
- 主要内容：原料编号、名称、单位、库存和状态。
- 额外检查：计件原料的库存应为整数，异常时在 `unit_check` 中显示。

不同单位不能直接相加，例如 g、ml 和个只能分别理解。项目没有确定低库存阈值，因此视图不自行添加库存预警标准。

**订单与退款依据（V06—V08）**

### V06 订单概要视图 vw_OrderSummary

供店员和店长查看订单列表、队列、退款资格和会员订单历史，对应 Q08、Q10、Q11、Q13。

- 来源表：SalesOrder、Member、OrderItem。
- 一行含义：一笔订单。
- 主要内容：下单时间、会员、状态、订单金额、明细行数和总杯数。
- 核对字段：`missing_items` 标记没有明细的订单，`amount_matches_items` 标记订单总额是否等于明细小计之和。

视图先按订单汇总 OrderItem，再连接订单和会员，避免一笔订单因多条明细而重复。非会员订单显示为“非会员”，没有明细的异常订单仍会保留。

### V07 订单详情视图 vw_OrderDetail

供店员查看每条订单明细的制作要求，对应 Q09，也可辅助 Q10。

- 来源表：SalesOrder、OrderItem、ItemSpec、ItemAddOn。
- 一行含义：一条订单明细。
- 主要内容：饮品快照、数量、糖度、温度、杯型、加料、成交单价和小计。
- 汇总方式：规格按类型分别整理，加料使用顿号连接成一段文字。

没有加料时显示“无加料”，缺少规格记录时显示“未记录”。视图使用订单中的历史名称和价格快照，不用当前商品名称和价格覆盖历史订单。

规格和加料先分别汇总，再连接订单明细，可以避免多规格和多加料相互连接造成重复行。

### V08 订单原料快照视图 vw_OrderIngredientUsage

供店长查看订单实际扣减的原料和当前可返库数量，对应 Q12。

- 来源表：SalesOrder、OrderItem、OrderItemIngredient、Ingredient。
- 一行含义：一笔订单使用的一种原料。
- 主要内容：保存用量、当前可返用量和退款资格说明。
- 汇总方式：同一订单中相同原料使用 `SUM(amount)` 合并。

`OrderItemIngredient.amount` 已包含该明细全部杯数，不能再乘 `quantity`。只有订单处于“排队中”，并且每条明细都有原料快照时，`refundable_amount` 才等于保存用量；其他状态显示为 0。

该视图只提供退款和返库依据，不会执行退款或修改库存。它能发现某条明细完全没有快照，不能证明一条已有快照的明细内部没有遗漏某种原料。

**会员消费（V09）**

### V09 会员消费视图 vw_MemberConsumptionStatistics

供店长查看会员累计消费和消费排名，对应 Q14。

- 来源表：Member、SalesOrder、OrderItem。
- 一行含义：一个会员。
- 主要内容：会员资料、当前积分、完成订单数、购买杯数、累计消费、平均订单金额及首次和最近消费时间。
- 统计规则：只计算已完成订单；先按订单汇总杯数，再按会员汇总。

视图从 Member 出发 LEFT JOIN 消费汇总，因此只有排队中订单或从未下单的会员也会保留，消费数据为 0。当前积分是会员表中的余额，可能包含期初积分，不能根据累计消费反推积分。

**员工与值班安排（V10—V11）**

### V10 员工排班视图 vw_DutyRosterDetail

供店长查看员工的值班安排，对应 Q15。

- 来源表：DutyRoster、Employee。
- 一行含义：一条员工班次。
- 主要内容：员工、岗位、当前状态和班次起止时间。
- 使用方式：可查询一段时间内相交的班次，也可查询某一时刻的值班人员。

查询某时刻时采用 `start_time <= 查询时刻 AND 查询时刻 < end_time`，避免交接时刻将上一班和下一班同时计算。月薪不放入通用排班视图，减少不必要的信息暴露。

### V11 订单值班团队视图 vw_OrderDutyTeam

供店长查看订单创建时的值班团队，对应 Q16。

- 来源表：SalesOrder、DutyRoster、Employee。
- 一行含义：一笔订单匹配的一条员工班次。
- 主要内容：订单、员工、岗位、班次时间和匹配状态。
- 匹配条件：`start_time <= order_time AND order_time < end_time`。

一笔订单可能匹配多名员工，因此出现多行是正常情况。订单使用 LEFT JOIN 连接排班，没有匹配班次的订单仍会保留，并显示“未匹配排班”。值班团队表示排班归属，不代表实际制作人，也不能直接计算个人销售额。

**经营统计（V12—V13）**

### V12 商品销量营业额视图 vw_ProductSalesStatistics

供店长按商品名称关键词和时间范围统计销量与营业额，对应 Q17。

- 来源表：SalesOrder、OrderItem。
- 一行含义：一笔已完成订单中的一种商品。
- 主要内容：订单、下单时间、商品历史名称、销售杯数和销售金额。
- 统计规则：只纳入状态为“已完成”的订单；同一订单中的相同商品先合并。

视图保留订单时间和商品历史名称，不固定关键词和日期。调用查询可以先按任意起止时间和名称关键词筛选，再按商品汇总。使用历史名称可以避免商品改名后覆盖已有订单，但同一商品在不同时期使用不同历史名称时，会按名称分别显示。

当前关系模式没有商品分类字段，所以 Q17 使用名称关键词表示品类。例如关键词“奶茶”会匹配珍珠奶茶和椰果奶茶。如果以后增加 Category 表，应改用分类编号建立正式的品类统计。

### V13 每日经营视图 vw_DailySalesStatistics

供店长查看每天的订单数、销量和营业额，对应 Q18。

- 来源表：SalesOrder、OrderItem。
- 一行含义：有已完成订单的一天。
- 主要内容：完成订单数、销售杯数、营业额、平均客单价、会员订单数和非会员订单数。
- 统计规则：只计算已完成订单；先按订单汇总杯数，再按订单日期汇总。

视图本身不生成没有销售的日期，因此 Q18 使用输入日期 LEFT JOIN 该视图，没有销售时仍返回一行 0。订单金额来自 SalesOrder，不能在直接连接多条 OrderItem 后重复累计。

## 2. 查询与视图对应关系

| 视图 | 对应查询 | 一行代表什么 |

| vw_ProductCatalog | Q01 | 一个商品 |
| vw_ProductSpecification | Q02 | 商品的一项规格配置 |
| vw_SpecificationIngredientRule | Q03 | 商品某规格的一种基础原料 |
| vw_AddOnAvailability | Q04 | 一种加料 |
| vw_IngredientStock | Q05 | 一种原料 |
| vw_OrderSummary | Q08、Q10、Q11、Q13 | 一笔订单 |
| vw_OrderDetail | Q09、Q10 | 一条订单明细 |
| vw_OrderIngredientUsage | Q12 | 订单的一种原料 |
| vw_MemberConsumptionStatistics | Q14 | 一个会员 |
| vw_DutyRosterDetail | Q15 | 一条班次 |
| vw_OrderDutyTeam | Q16 | 订单匹配的一条班次 |
| vw_ProductSalesStatistics | Q17 | 一笔已完成订单中的一种商品 |

Q06 和 Q07 没有建立普通视图。它们需要接收顾客临时选择的商品、规格、加料和数量，而普通视图不能接收参数，所以购买试算和库存检查继续保留在 `query.sql` 中。Q17 的关键词和起止时间由调用查询填写；Q18、Q14 分别使用每日经营和会员消费视图。

## 3. 创建与使用方法

数据库初始化完成后执行：

```text
db_creation.sql → seed_data.sql → view.sql
```

`view.sql` 开头已经选择 TeabarDB。文件使用 `CREATE OR ALTER VIEW`，第一次执行会创建视图，再次执行会更新视图，不需要手动删除。

创建完成后，视图可以像普通表一样查询。例如查看 O001 的制作清单：

```sql
SELECT order_id, item_id, product_name_snapshot, quantity,
       sugar, temperature, cup, addons, unit_price, sub_amount
FROM dbo.vw_OrderDetail
WHERE order_id = 'O001'
ORDER BY item_id;
```

查看 2026-10-04 全天“奶茶”类商品的销量和营业额：

```sql
SELECT product_id, product_name,
       COUNT(DISTINCT order_id) AS completed_order_count,
       SUM(cups_sold) AS cups_sold,
       SUM(sales_amount) AS sales_amount
FROM dbo.vw_ProductSalesStatistics
WHERE order_time >= '2026-10-04T00:00:00'
  AND order_time < '2026-10-05T00:00:00'
  AND product_name LIKE N'%奶茶%'
GROUP BY product_id, product_name
ORDER BY sales_amount DESC, product_id;
```

查看 2026-10-04 当日经营情况：

```sql
SELECT business_date, completed_order_count, cups_sold,
       sales_amount, average_order_amount,
       member_order_count, nonmember_order_count
FROM dbo.vw_DailySalesStatistics
WHERE business_date = '2026-10-04';
```

查看会员累计消费排名：

```sql
SELECT member_id, member_name, completed_order_count,
       cups_purchased, total_spending, last_purchase_time
FROM dbo.vw_MemberConsumptionStatistics
ORDER BY total_spending DESC, member_id;
```

视图中不固定商品编号、订单编号、日期范围和排序规则。这些条件由实际调用查询填写，使同一个视图可以服务多个业务场景。
