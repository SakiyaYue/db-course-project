# v0.1 ER 设计源

本目录提供 v0.1 清晰导出图 [`ER图_v0.1.png`](ER图_v0.1.png) 和可编辑 Mermaid 源 [`ER图_v0.1.mmd`](ER图_v0.1.mmd)。PNG 复制自仓库根目录的修订图，Mermaid 源依据冻结 SQL 和对象清单重建；阅读两种图时，均需配合下方的图例与候选码补充说明。

可编辑源与导出图共同表达以下内容：

- 15 张业务表与 `teabar_auth.PrincipalBinding` 辅助表；
- 主码、显式唯一约束、外码和联合码；推导候选码见下方附表；
- `0..1`、`1..1`、`0..N`、`1..N` 等最小/最大基数；
- 外键联系与值班时间匹配、购买身份核对等非外键业务联系的区别；
- 每条明细至少一条消耗快照目前是未完整落实的业务下限。

## 图例与候选码补充说明

`PK` 表示主码，`FK` 表示外码，`UK`（源文件中也写作 `UNIQUE`）表示 SQL 显式唯一约束；`?` 或 `nullable` 表示可空。主码本身是候选码；其他唯一属性组合只有满足最小性才是候选码，因此不能把所有 UK 都解释为候选码。

以下附表是 Mermaid 源与 PNG 的共同图注，补充图中尚未直接标出的推导候选码及容易混淆的唯一组合：

| 对象与属性组合 | 分类 | 推导依据与保证范围 |
| --- | --- | --- |
| `DutyRoster(employee_id, end_time)` | 业务规则下的候选码；无单独 SQL UNIQUE | 值班区间非空且同员工区间不重叠时，相同结束时刻的两段区间必然重叠，因此组合唯一；员工编号或结束时刻单独均不唯一。非重叠规则由 `usp_SaveDutyRoster` 保证，直接绕过过程写表时不由此组合的 UNIQUE 保证 |
| `ItemSpec(item_id, spec_id)` | 由现有约束推导的候选码；无单独 SQL UNIQUE | `Specification` 主码及复合 FK 保证 `spec_id → spec_type`，再结合 `ItemSpec` 主码 `(item_id, spec_type)` 可确定整行；`item_id` 或 `spec_id` 单独均不唯一 |
| `Specification(spec_id, spec_type)` | 显式唯一超码，不是候选码 | `spec_id` 已单独唯一，该组合不满足最小性；保留 UNIQUE 是为了让 `ItemSpec` 的复合 FK 同时核对选项与类型 |

逐表主码和其他候选码见[实体与码分析](实体与码分析.md)；理论依据见week6的[函数依赖与范式分析]
