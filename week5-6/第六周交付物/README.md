## 2. 主要设计结论

基线 16 张表中，14 张在已列业务依赖下满足 BCNF；`ItemSpec` 满足 3NF，保留规格类型冗余以直接约束“一明细一类型至多一个选项”；含计算小计的完整 `OrderItem` 关系满足 2NF，其基础事实投影满足 BCNF。

v1.0 保留原业务表和历史快照，新增 7 列 `WebAccount`、3 个索引、3 个过程，并在核心下单过程增加逐明细正消耗校验。原 16 表的历史数据保留，迁移后为 17 表、81 列、19 条外键。

## 3. 复现入口

在完整 v0.1 的 `TeabarDB` 基础上，依次执行：

```text
SQL脚本/数据库迁移脚本/work-copy.sql
→ SQL脚本/数据库迁移脚本/migration.sql：0/0 默认演练
→ SQL脚本/数据库测试脚本/verify-rollback.sql
→ SQL脚本/数据库迁移脚本/migration.sql：0/1 故障演练
→ SQL脚本/数据库测试脚本/verify-rollback.sql
→ SQL脚本/数据库迁移脚本/migration.sql：1/0 正式提交
→ SQL脚本/数据库测试脚本/v1.0-object-capture.sql
→ SQL脚本/数据库测试脚本/regression.sql
→ SQL脚本/数据库测试脚本/key-query-compare.sql
```

副本创建与迁移入口位于 `SQL脚本/数据库迁移脚本/`，核验、回归与查询入口位于 `SQL脚本/数据库测试脚本/`。提交版 `work-copy.sql` 默认 `Execute=0`，`migration.sql` 默认 `CommitMigration=0, InjectFailure=0`；本人实际提交时使用的 `1/0` 配置见实操记录第 6 张图。详细步骤见[迁移与恢复说明](迁移与恢复说明.md)。

[business-query-compare.sql](SQL脚本/数据库测试脚本/business-query-compare.sql) 补充订单明细、逐商品销量及全部原料库存的只读对照，可在迁移前后分别运行并保存结果。[source-integrity.sql](SQL脚本/数据库测试脚本/source-integrity.sql) 用于在冻结源库采集指纹。
